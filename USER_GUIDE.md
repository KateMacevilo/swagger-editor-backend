# Swagger Editor — инструкция для пользователя

Руководство для тех, кто работает с редактором только через веб-интерфейс.
Никакой настройки и установки не требуется — нужен только браузер и адрес, где развёрнут редактор.

---

## 1. Главная страница (список проектов)

Открывается по корневому адресу редактора. Здесь находятся все проекты.
Проект — это один OpenAPI-документ (спецификация API). Все проекты хранятся
в общем репозитории GitLab: «Сохранить на GitLab» делает коммит, удаление
проекта удаляет его файл из репозитория.

Доступные действия:

- **Создать проект** — ввести название (обязательно) и необязательные
  описание, версию, URL сервера → «Создать». Откроется пустой редактор.
- **Импортировать** готовую спецификацию — кнопка импорта, файл JSON или YAML
  до 10 МБ. Проект создаётся сразу с эндпоинтами и схемами из файла.
  Если проект с таким названием уже есть — файл обновится.
- **Открыть проект** — клик по строке в списке.
- **Переименовать / удалить** — кнопки в строке проекта. При переименовании
  проект переносится в GitLab в папку с новым именем.

> Подсказка: короткие уникальные названия проектов удобнее — из названия
> формируется имя папки в репозитории.

## 2. Редактор: общий вид

Страница проекта разделена на три панели:

```
┌────────────┬──────────────────────┬──────────────────┐
│  Эндпоинты │  Форма редактирования│  Swagger UI /    │
│  + экспорт │  эндпоинта           │  сырой JSON      │
└────────────┴──────────────────────┴──────────────────┘
```

Обе серые полоски-разделители между панелями **двигаются мышкой**:
потяните влево/вправо, чтобы расширить панель эндпоинтов или превью.
Полезно на маленьких экранах и при длинных путях эндпоинтов.

---

## 3. Левая панель: эндпоинты и действия

- Список эндпоинтов с методом (GET, POST, …) и путём. Клик — открыть в форме.
- Клик по эндпоинту **в правой панели превью** тоже открывает его в форме.
- **+ Добавить эндпоинт** — новый эндпоинт открывается в форме по центру;
  он появится в списке после сохранения.
- ✕ у эндпоинта — удалить (после подтверждения).
- **Сохранить на GitLab** — записывает весь проект в репозиторий коммитом.
  Сохраняйте перед уходом: несохранённые изменения живут только в браузере.
- **Экспорт спецификации** — кнопки JSON / YAML скачивают готовый
  OpenAPI-файл, его можно отдать разработчикам или импортировать куда угодно.
- **Компоненты схем (N)** — окно со всеми компонентами проекта
  (см. раздел 7).
- **Настройки проекта** — иконка в шапке (см. раздел 8).

## 4. Центральная форма: эндпоинт

Поля вверху:

- **Метод** — GET, POST, PUT, DELETE, PATCH, OPTIONS, HEAD.
- **Путь** — например `/payments/{paymentId}`. Лишние пробелы в конце
  удаляются автоматически. Параметры пути (`{paymentId}`) должны совпадать
  по имени с параметрами типа `path` на вкладке «Параметры».
- **Summary** — короткое название операции (видно в Swagger UI).
- **Описание** — подробности, поддерживается Markdown.
- **Tags** — группировка в Swagger UI. Тег может быть любым текстом,
  включая запятые.
- **Deprecated** — пометить операцию устаревшей.
- **Требует авторизации** — включить OAuth2 для этого эндпоинта
  (работает, если включена авторизация в настройках проекта).

Ниже — три вкладки.

### 4.1. Параметры

Query, path, header и cookie-параметры. У каждого:

- имя (обязательно; пробелы в имени удаляются автоматически);
- расположение: query / path / header / cookie;
- тип: string, integer, number, boolean, array (у массива — тип элементов);
- формат (для string — date, date-time, uuid и т.п., для чисел — int32/int64/double…);
- **min / max** — значение для чисел, длина для строк, количество элементов для массивов;
- **«18,2»** (только для number) — разрядность: всего цифр и после запятой.
  В спецификацию добавится pattern автоматически;
- описание (Markdown);
- **Пример** — поле можно растянуть мышкой, если пример длинный;
- **req** — обязательный параметр.

### 4.2. Request Body

Вкладка есть у POST, PUT, PATCH. Тело описывается конструктором схем
(см. раздел 6). Всегда `application/json`.

### 4.3. Ответы

Список ответов с HTTP-статусом (200, 400, 404, 422 …). У каждого:

- статус и описание (обязательно);
- схема тела ответа — тот же конструктор (раздел 6);
- **header'ы** — имя и описание заголовков ответа.

Если ответы не заданы, в спецификацию автоматически добавится `200 OK`.

> Типовой приём: описать ошибки (ErrorResponse400, ErrorResponse403…)
> один раз как компоненты, а в каждом эндпоинте выбирать их из списка
> ссылкой ($ref). Поправите компонент — исправится везде.

## 5. Быстрый старт: эндпоинт «с нуля»

1. «+ Добавить эндпоинт» → выбрать метод POST, ввести путь.
2. Вкладка Request Body → «↑ загрузить пример JSON» → вставить пример
   реального запроса → «Применить». Конструктор сам разложит пример на поля
   с типами (объекты и массивы объектов тоже).
3. Поправить типы, обязательность, описания, min/max.
4. Вкладка Ответы → добавить 200, вставить пример ответа или выбрать
   готовый компонент.
5. «Сохранить на GitLab».

## 6. Конструктор схем (тела запросов/ответов и компонентов)

Работает одинаково для request body, ответов и компонентов.

**Режимы (вкладки вверху блока):**

- **Конструктор** — визуальное дерево полей.
- **Raw JSON** — сырой JSON-схемы; чекбокс «форматировать» приводит
  JSON в читаемый вид с отступами.
- **Компоненты** — список всех компонентов проекта с поиском,
  кратким составом и кнопкой «выбрать».

**В конструкторе** у каждого поля: имя, тип, описание, пример, обязательность
и ограничения (раздел 4.1). Типы: string, integer, number, boolean, array, object.

- **object** — раскрывается вложенным списком полей (можно вкладывать друг в друга).
- **array** — указывается тип элементов: примитив, объект (вложенный конструктор)
  или **ссылка на компонент** (`→ ссылка ($ref)`).
- **→ ссылка ($ref)** — поле ссылается на компонент: выбрать имя из списка.
  Кнопка «структура» показывает состав компонента прямо здесь.
- Кнопка **«сохранить как компонент»** превращает текущую схему в компонент
  и заменяет её ссылкой — удобно для переиспользования.

**Кнопка «↑ загрузить пример JSON»** строит схему из примера
(вставить текстом или выбрать файл .json).

## 7. Компоненты схем

Компонент — это именованная схема (`#/components/schemas/Имя`), общая
для всего проекта. Окно «Компоненты схем» на левой панели:

- поиск по имени;
- у каждого компонента — краткий состав и раскрываемая структура
  (вложенные ссылки можно разворачивать деревом);
- **переименование** — карандаш; все ссылки в эндпоинтах обновятся автоматически;
- **удаление** — мусорка; будьте осторожны: ссылки `$ref` на удалённый
  компонент «повисят» (в спецификации останется несуществующая ссылка).

Если открыть тело эндпоинта, которое ссылается на компонент, редактор
покажет предупреждение и даст отредактировать ссылку вручную.

---

## 8. Настройки проекта

Иконка в шапке редактора. Поля: название, описание, версия, URL сервера,
описание сервера, контактный email, лицензия, Terms of Service.

Блок **OAuth2-авторизация**: включает глобальную схему безопасности
(кнопка Authorize в Swagger UI). Задайте Authorization URL и scopes
(пары имя=описание). На отдельных эндпоинтах требование авторизации
переопределяется чекбоксом «Требует авторизации».

Изменение названия проекта **переименует** его и в GitLab (папка проекта).

---

## 9. Правая панель: превью

- **Swagger UI** — живая документация по текущему состоянию проекта,
  обновляется автоматически (~через полсекунды после изменений).
  Клик по операции в превью открывает её в форме редактирования.
- **Вкладка JSON** — сырой JSON сгенерированной спецификации,
  с чекбоксом удобного форматирования.

Превью — лучший способ проверить, как спецификация будет выглядеть
для потребителей API, до сохранения и экспорта.

---

## 10. Важно помнить

- **«Сохранить на GitLab» перезаписывает проект целиком** — отдельного
  слияния изменений нет. Если двое правят один проект одновременно,
  выигрывает тот, кто сохранился последним.
- До сохранения всё живёт только в вашем браузере — не закрывайте вкладку,
  не сохранившись.
- Имена параметров и пути очищаются от пробелов автоматически —
  не используйте пробелы как часть имён.
- Экспорт JSON/YAML ничего не сохраняет на сервер — это просто скачивание файла.
